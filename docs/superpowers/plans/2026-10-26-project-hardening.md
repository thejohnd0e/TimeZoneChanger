# План исправлений и улучшений TimeZone Changer

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Не начинать реализацию без отдельного запроса пользователя.

**Goal:** Устранить обнаруженные ошибки подмены времени, состояния вкладок и управления правилами, затем проверить расширение в Chrome.

**Architecture:** Сохранить Manifest V3, разделение background/content/page world и существующую модель хранилищ. Исправления выполнять небольшими независимыми изменениями, начиная с воспроизводящих проверок. Изменение механизма ранней инъекции выделить в отдельный этап после проверки в браузере.

**Tech Stack:** JavaScript, Chrome Extensions API (MV3), Date/Intl; для предлагаемых новых автоматических проверок — встроенные `node:test`, `node:assert/strict`, `node:vm`, без npm-зависимостей.

**Spec:** Основание — аудит в текущем диалоге и `AGENTS.md`. Отдельная согласованная спецификация отсутствует; решения, перечисленные ниже, являются предложениями, а не утверждёнными требованиями.

## Ограничения

- Сейчас в проекте нет build/test/lint-скриптов и package.json; не использовать вымышленные npm/yarn-команды.
- Предлагаемые файлы `tests/*.test.cjs` создаются только при реализации. Упомянутые ниже команды тестирования до этого не существуют как готовый набор проверок.
- `shared.js` должен оставаться без зависимостей от DOM/window.
- Рабочая логика подмены находится в `spoof.js`; `inject.js` не подключён manifest.
- Не менять посторонние пользовательские правки и не добавлять их в коммиты.
- Не выполнять push и не публиковать новую версию без отдельного разрешения.
- Моки Chrome API и Node VM не заменяют загрузку unpacked-расширения в Chrome.
- Сохранять явный `timeZone`, переданный сайтом, и поведение UTC API.

## Статус доказательств

В Node.js воспроизведены: дробное смещение и повреждённый GMT, расхождение локальных методов Date, исключение для Invalid Date, потеря унаследованного timeZone, расхождение приоритетов, гонка первой загрузки состояния вкладок и закрепление fallback до определения IP. Гонка и сценарий определения IP проверялись с моками Chrome API.

Статически обнаружены: отсутствие валидации поясов, неполное восстановление формы popup, отсутствие явного тайм-аута и неполная обработка ошибок.

Ранняя инъекция, влияние CSP, iframe и workers требуют проверки в Chrome; это не подтверждённые браузерные результаты аудита.

## Решения перед изменением поведения

- [ ] Согласовать приоритет правил. Код: tab override → exclusions/whitelist → site rule → default. README и UI: tab override → site rule → exclusions/whitelist → default. Не переставлять проверки молча: это может изменить защиту Google/Gemini.
- [ ] Согласовать срок блокировки auto. README обещает блокировку на жизнь вкладки; `AGENTS.md` упоминает повторное определение после reload, но обработчика сброса сейчас нет. Предложение: сохранять успешно определённый пояс на жизнь вкладки, не закрепляя временный fallback.
- [ ] Согласовать полный объём совместимости Date: локальные getters/setters, многопараметрический конструктор, разбор строк без пояса и вызов `Date()` без `new`. Это отдельная сложная задача, а не простая замена `getHours()`.
- [ ] Подтвердить добавление Node-проверок без package.json и сторонних зависимостей.

## Review Focus

## Критерии завершения

- Найденные регрессии имеют проверки, падавшие до исправлений и проходящие после.
- Состояние нескольких вкладок не теряется при одновременном первом обращении.
- Невалидный пояс не попадает в рабочую инъекцию и не ломает API страницы.
- Auto не блокируется навсегда на временном системном fallback.
- Интерфейс корректно восстанавливает правила и сообщает об ошибках.
- Реальные приоритеты и поведение lock совпадают с документацией.
